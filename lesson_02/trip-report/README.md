# Отчёт по поездке

**Студент:** Марущак Сергей, группа РПО 25/2

Программа считает расходы поездки и печатает отчёт таблицей Rich.

**Python:** 3.12.3

Путь интерпретатора из активированного `.venv` (команда
`python -c "import sys; print(sys.executable)"`):

```text
ВСТАВИТЬ СВОЙ ПУТЬ
```

Этот путь снимается на своём компьютере. На чужой машине он будет другим,
поэтому в репозиторий кладётся не само окружение, а `requirements.txt`.

## Структура

```
trip-report/
├── app/__init__.py
├── app/main.py                   данные поездки, вызовы расчётов, печать
├── app/services/calculator.py    только расчёты, ничего не печатает
├── app/utils/formatter.py        только таблица отчёта
├── tests/test_calculator.py      тесты расчётов
├── requirements.txt              зависимости, снятые через pip freeze
├── .gitignore
└── README.md
```

Расчёты не печатают текст и не собирают таблицу. Оформление не складывает
суммы. `main.py` только соединяет части.

## Команды

Linux и macOS, из папки `trip-report`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.main
python -m unittest discover -s tests -v
```

Windows (PowerShell):

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.main
python -m unittest discover -s tests -v
```

`python app/main.py` падает с `ModuleNotFoundError`: при прямом запуске файла
корень проекта не попадает в пути поиска. Запускать нужно через `python -m`.

## Почему `.venv` не кладут в репозиторий

Окружение собирается заново на каждом компьютере. Внутри лежат бинарные
файлы под конкретную систему и абсолютные пути. В Git от этого нет пользы,
а чужой компьютер из такого каталога проект не поднимет. Зависимости
записаны в `requirements.txt`, по нему окружение создаётся командами выше.

## Проверка на чистом месте

Папка скопирована без `.venv`, окружение собрано заново командой
`pip install -r requirements.txt`. Тесты прошли, отчёт напечатал те же числа.
